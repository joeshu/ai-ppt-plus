# Narrative strategy

Use after source analysis and before outline drafting. Input is the brief, evidence inventory and constraints; output is a selected arc, section logic, page purpose map and deletion/merge decisions.

Choose a narrative only after reading source evidence and the deck brief.

| Goal | Default arc | Observable fit |
|---|---|---|
| Decision | context → problem → evidence → options → recommendation → action | audience must approve or choose |
| Operating review | target → actual → variance → cause → intervention → owner/date | formal metrics and accountable actions exist |
| Proposal | need → insight → solution → value → proof → plan → ask | proposed change and decision request exist |
| Teaching | objective → concept → example → practice → recap | learning outcome is explicit |
| Status | objective → progress → risks → decisions → next steps | time-bounded workstream exists |

For every slide write `purpose`, `takeaway`, `previous_link`, `next_link`, `must_keep`, and `remove_or_merge`. Use assertion-led titles when evidence supports them. Do not split one idea merely to hit a page count or combine claims whose evidence differs.

Ask the user when two arcs imply materially different decisions. Otherwise select the arc whose observable fit matches the brief and record the reason.

Judge agenda and section dividers by navigation need: use them when the deck has at least three distinct sections or the live setting needs explicit wayfinding; omit them when they add no decision value. Facts retain provenance; interpretations are labeled.

Positive example: a board decision deck moves from variance evidence to options and a clear ask. Negative example: pages follow source-file order although that order does not support a decision.

Common failures are audience mismatch, unsupported assertion titles, page-count padding and mixed evidence scopes. Validate that every page advances the goal, has one takeaway, connects to neighbors and cites its evidence.
