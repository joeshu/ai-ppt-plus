# PPT 思路表（表格思路法）

## 作用

在任何视觉设计、生图或 PPTX 工程之前，先把杂乱的立项材料、专项汇报、项目说明、会议纪要和讨论沉淀整理成一份可审阅的叙事原型。这个阶段只解决两件事：整份汇报讲什么，以及每一页为什么存在。

## 用户先看到的四列

| 列 | 作用 | 规则 |
|---|---|---|
| 页码 | 明确页序 | 从 1 开始连续编号；改序要进入修订记录 |
| 标题 / 核心思想 | 写出这一页要让听众记住的一句话 | 一页一个核心结论，不用视觉语言代替结论 |
| 页面大纲 | 说明本页具体讲什么、保留什么证据 | 先写内容和关系，不写装饰堆砌 |
| 我的修改意见 | 留给用户快速批注 | 原文保留；AI 只能据此提出新修订，不能静默覆盖 |

可以在这四列之后增加 `status`、`data_sources`、`section`、`visual_type`、`revision_reason` 等治理列。它们服务于追溯和自动校验，不改变用户的四列审阅体验。

## O0–O4 流程

1. **O0 材料扫读**：建立来源清单，标出权威性、冲突、缺失事实、待验证项和可引用位置。
2. **O1 AI 初稿**：只生成思路表；前三列由 AI 起草，`我的修改意见` 留空或保留用户原话。状态为 `draft` / `needs_user`。
3. **O2 用户审阅**：用户直接写“提前”“拆开”“结论太技术”“突出业务价值”等结构意见。这里不追求页面漂亮。
4. **O3 叙事修订**：复制出新修订版本，按批注调整页序、核心思想、页面大纲和删拆合并关系；保留原表、批注和变更记录。
5. **O4 明确批准**：所有正式页状态为 `approved`，关键事实有来源，页码连续，批准人和时间已记录，才可进入视觉设计与生图。

## 生图前的硬闸门

- 主题或未经批准的初稿只能停留在思路表审阅阶段，不能直接调用图像模型。
- `visual-generation-plan.json` 必须指向本次实际使用的思路表，并记录其 SHA-256、修订号和批准信息。
- 正式页面文字的唯一权威是已批准思路表/正式文案；视觉稿中的错字、伪文字和临时标签不得回写成正式内容。
- 用户批注必须可追溯；批注导致的改动必须产生新修订和 change log。

## 视觉稿的高端商业质量目标

思路表批准后，才把文字大纲交给同一图像模型、同一连续上下文批量生成整套视觉稿。每页应有明确焦点、可见阅读路径、稳定标题基线、统一页脚/组件节奏、展示级字号和足够留白；“豪华”来自层级、材质、精确对齐、克制光影和高价值语义图形，而不是霓虹 HUD、无意义英文标签、随机图标或填满页面。

商业交付还要显式排除水印、未授权 Logo、名人/商标/品牌仿冒和无来源外部素材；外部素材必须保留来源或授权记录。画布尺寸、可读性和连续生成会话都进入 manifest，无法满足时阻断，不静默降级。

## 校验

```bash
python3 scripts/validate_outline_table.py PROJECT/outline/PPT思路表.xlsx \
  --require-approved \
  --report PROJECT/qa/outline-validation.json
```

只有校验通过的思路表，才能让 `ai-ppt-visual-gen` 进入 A1–A5。
